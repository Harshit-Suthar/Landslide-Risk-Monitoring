1. WHAT IS THIS PROJECT?
--------------------------------------------------------------------------------
The Landslide Early Warning & Risk Monitoring System is a web platform built 
to protect people living in the hilly areas of North East India (such as 
Meghalaya, Assam, Mizoram, Nagaland, and Arunachal Pradesh).

In these regions, heavy rainfall during monsoon seasons frequently triggers 
dangerous landslides and road blockages. This platform solves that problem by:

  * Allowing Citizens to Report Incidents: 
    Anyone can take a picture of a landslide or road crack, tag their GPS 
    location, and send it immediately to authorities.

  * Helping Officers Verify Reports: 
    Disaster management teams can review the photos and confirm whether the 
    danger is real.

  * Using AI to Predict Landslide Risk: 
    The system looks at current rainfall, soil wetness, how steep the mountain 
    is, and past landslide history to calculate a risk level 
    (Low, Medium, High, or Critical).

  * Sending Instant Emergency Alerts: 
    If a landslide is confirmed or risk is critical, the system sends SMS 
    warnings and push notifications to residents and district officers.

Detailed Step-by-Step Sub-Workflows:
................................................................................

A. Citizen Reporting Workflow:
   1. A citizen or field agent opens the "Report Incident" page on their mobile 
      or desktop browser.
   2. They select what happened (Landslide, Slope Crack, Road Blockage, or 
      Flooding) and select the severity (Minor, Moderate, Severe).
   3. The device GPS automatically detects the exact latitude and longitude.
   4. They attach a photo or video as evidence.
   5. Clicking "Submit" uploads the photo to cloud storage and creates the 
      report in the database with status "Pending".
   6. A notification is sent automatically to the emergency control room.

B. Officer Verification Workflow:
   1. The disaster response officer logs into the Admin Console and opens the 
      "Reports" screen.
   2. They see incoming citizen submissions waiting for review.
   3. The officer checks the photo evidence, map location, and description.
   4. If genuine, the officer clicks "Verify" (or "Reject" if false/duplicate).
   5. Once verified, the database updates to "Verified" and alerts are triggered.

C. AI Risk Prediction Workflow:
   1. The system or officer triggers a risk prediction for a specific hill or 
      district.
   2. The AI model evaluates 4 key factors:
      * Rainfall (35% weight): Amount of rain fallen in the last 24 hours.
      * Soil Wetness (25% weight): How saturated the ground is with water.
      * Hill Slope (25% weight): How steep the mountain gradient is.
      * Past History (15% weight): Number of past landslides in that zone.
   3. The model outputs a composite hazard tier:
      * Low: Safe conditions.
      * Medium: Caution advised; monitor rainfall.
      * High: Dangerous; potential slope instability.
      * Critical: Extreme danger; evacuation/road closure recommended.
   4. It provides plain-language explanations of why the score was assigned.

D. Emergency Alert Workflow:
   1. When an incident is verified or risk is Critical, alerts are dispatched.
   2. The system sends:
      * SMS: Direct text message to mobile numbers in the district.
      * Web Push: Pop-up notification on subscribed phones/browsers.
      * Email: Formal alert sent to District Disaster Management Authorities.

3. TECHNOLOGY STACK (TOOLS USED)
--------------------------------------------------------------------------------

Layer                   Tool               What It Does
--------------------------------------------------------------------------------
Frontend (User UI)      React              Builds web pages, forms, and screens.

4. PROJECT FOLDERS (WHERE EVERYTHING LIVES)
--------------------------------------------------------------------------------

  * frontend/
    The website users and officers see in their browser.
    - src/pages/        : Home page, Login, Citizen screens, Admin screens.
    - src/components/   : Reusable parts like maps, charts, and buttons.
    - src/services/     : Functions that fetch and send data to the backend.

  * backend/
    The Node.js server running in the background.
    - src/routes/       : Defines API links for reports, weather, and alerts.
    - src/controllers/  : Business logic handling each API request.
    - src/providers/    : Modules for weather data, SMS, and notifications.

  * ml-services/
    The Python AI risk prediction engine.
    - app/services/     : Formula calculating risk (Low, Medium, High, Critical).
    - app/routers/      : Prediction API endpoint (/predict).

  * supabase_schema.sql
    Database setup file containing tables, security rules, and sample data.

5. DATABASE STRUCTURE (HOW DATA IS STORED)
--------------------------------------------------------------------------------

1. USERS TABLE
   Stores accounts for people who can log into the system:
   - Name       : User's full name.
   - Email      : Unique login email address.
   - Role       : Admin, District Officer, Field Agent, or Citizen.
   - District   : Assigned district (e.g., Shillong, Kohima, Aizawl).
   - Status     : Active or Inactive.

2. LOCATIONS TABLE
   Stores known landslide-prone sites and hills being monitored:
   - Name       : Name of the hill or road corridor.
   - District   : District name.
   - Lat & Lon  : Exact GPS coordinates.
   - Risk Level : Current danger level (Low, Medium, High, Critical).
   - Status     : Monitored or Resolved.

3. REPORTS TABLE
   Stores all incident submissions from citizens and field agents:
   - Incident   : Landslide, Slope Crack, Road Blockage, or Flooding.
   - Location   : District name and GPS coordinates.
   - Description: Details written by the citizen.
   - Media URL  : Web link to the uploaded photo or video.
   - Severity   : Minor, Moderate, or Severe.
   - Status     : Pending, Verified, or Rejected.

4. MEDIA STORAGE BUCKET (incident-media)
   - Secure cloud storage holding citizen photos and videos.
   - Supports JPEG, PNG, WebP, and MP4 files up to 50MB each.

Relationships in Plain Words:
  * One user can submit multiple reports over time.
  * Each report's GPS coordinates can be viewed on the map.
  * When an officer verifies a report, status changes from Pending to Verified, 
    triggering emergency alerts.

6. API REFERENCE (SIMPLE & CLEAR)
--------------------------------------------------------------------------------

1. REPORT APIS:
   - Verify or Reject Report
     Link: PATCH /api/admin/reports/:id/verify
     What it does: Approves (Verify) or declines (Reject) a citizen report.
     Extra info: If verified, automatically alerts district disaster teams.

   - Citizen Report Notification
     Link: POST /api/citizen/reports/notify
     What it does: Tells the control room that a new report was submitted.
     Extra info: Sends email and push notifications to the duty desk.

2. AI RISK PREDICTION API:
   - Calculate Landslide Risk
     Link: POST /api/admin/ai-model/predict
     What it does: Calculates risk level (Low, Medium, High, Critical).
     Extra info: Automatically looks up local rainfall if not supplied.

3. EMERGENCY ALERT API:
   - Send District Alert
     Link: POST /api/alerts/send
     What it does: Broadcasts emergency SMS and push alerts to a district.
     Extra info: Used during severe landslides or road closures.

4. WEATHER API:
   - Get District Weather
     Link: GET /api/weather/:district
     What it does: Gets 24-hour rainfall in mm and a 7-day forecast.
     Extra info: Used on the home page and by the AI prediction model.

5. DASHBOARD SUMMARY API:
   - Get Dashboard Statistics
     Link: GET /api/admin/dashboard/stats
     What it does: Returns counts of locations, pending reports, and risk levels.
     Extra info: Powers the summary cards and charts in the admin console.

6. SYSTEM HEALTH API:
   - Check Server Status
     Link: GET /api/health
     What it does: Confirms that the backend server is online and operational.

7. HOW TO RUN THE PROJECT LOCALLY
--------------------------------------------------------------------------------

1. Database Setup:
   - Open your Supabase project SQL Editor.
   - Paste and run the code from "supabase_schema.sql".

2. Start the Backend API (Node.js):
   - Open a terminal and run:
       cd backend
       npm install
       npm run dev
   - Server runs on: http://localhost:5000

3. Start the AI Service (Python):
   - Open a terminal and run:
       cd ml-services
       python -m venv venv
       venv\Scripts\activate       (On Windows)
       source venv/bin/activate    (On Mac/Linux)
       pip install -r requirements.txt
       uvicorn app.main:app --reload --port 8000
   - Service runs on: http://localhost:8000

4. Start the Frontend Website (React):
   - Open a terminal and run:
       cd frontend
       npm install
       npm run dev
   - Open your browser at: http://localhost:5173
